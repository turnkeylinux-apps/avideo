# AVideo 19.0 testing

## Scope and source decision

Debian 13 Trixie does not package the WWBN AVideo application. The similarly
named `python3-mecavideo` package is unrelated. AVideo 19.0 therefore installs
the official AVideo 29.0 and AVideo Encoder 8.0 Git tags. The build pins the
tags to these exact commits and fails if either tag resolves differently:

| Component | Release | Commit |
| --- | --- | --- |
| AVideo Streamer | 29.0 | `2386f39caea1d2ef36267b252fa76af283294623` |
| AVideo Encoder | 8.0 | `71759ba94928bd324b6171b53b1d3e9e43760b91` |

The build and runtime both run `git fsck --strict` against the installed
checkouts. The deterministic playback fixture is the pinned Streamer release's
`install/assets/testVideo.mp4`, with SHA-256 digest
`160f70c0fc49b0542948e545c80f7d2d91ad4e82b396a1541c3750dc28274a4a`.

PHP 8.4, MariaDB, Apache XSendFile, FFmpeg, ExifTool, Nginx RTMP and yt-dlp
come from signed Debian Trixie repositories. Encoder 8.0 still invokes the
historical `youtube-dl` executable name, so the appliance provides that name
as a compatibility link to Debian's `/usr/bin/yt-dlp`. The package manager
remains the only updater for that executable.

## Acceptance command

```sh
/sandboxed-git/turnkey/tools/test-v19-appliance avideo \
    --source /home/agent/.local/worktrees/turnkey-apps/avideo/wish-avideo-v19-trixie
```

This command builds the Trixie appliance, imports it into Docker, boots the
normal systemd and firstboot path, then runs `tests/v19.sh`. The retained
harness report and its adjacent `SHA256SUMS` file are the authoritative result
and checksum record for the exact tested source commit.

## Update path

AVideo upstream recommends Git updates followed by database migrations. The
appliance keeps both official Git checkouts and provides a release-oriented
wrapper that requires the administrator to supply the reviewed release tag
and its full expected commit. It refuses modified tracked files, an unexpected
origin, an invalid tag, or a fetched commit that differs from the expected
commit. After checkout it applies ordered Streamer or Encoder database
migrations and restarts Apache.

Check the official tag channel without changing application files:

```sh
avideo-update --check streamer
avideo-update --check encoder
```

After reviewing upstream release notes, taking an off-host backup, and
recording the tag's full commit, update each component explicitly:

```sh
avideo-update streamer RELEASE EXPECTED_COMMIT
avideo-update encoder RELEASE EXPECTED_COMMIT
```

`tests/v19.sh` exercises the complete helper with the installed release and
commit. Both fetches must resolve to the expected commit, both database paths
must report their current schema version, Apache must restart, and the web
endpoint must remain available. It also refreshes signed APT metadata and
confirms that the installed Debian package versions do not change during the
candidate check.

## Deferred issues

The Docker acceptance run checks the RTMP listener and HLS configuration, but
does not publish a real live broadcast. It also avoids an external provider
URL import because that would depend on third-party content and extractor
behavior. The local, Debian-owned downloader boundary is checked instead.

The obsolete `plugin/LiveChat/chat-server.php` entry point no longer exists in
AVideo 29.0, so the broken legacy service and WebSocket proxy are removed.
Configuring a current optional chat plugin is separate feature work.

Docker runtime validation does not exercise the installer, kernel, bootloader
or physical hardware. AVideo adds no appliance-specific behavior at those
boundaries, so the passing Core 19 baseline supplies inherited evidence.
